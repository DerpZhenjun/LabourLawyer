# 商业化缺口修复 Implementation Plan

**Goal:** 依次修复已确认的安全、覆盖、部署、同步和发布缺口，不把局部通过当全国完成。
**Architecture:** 保留免登录群众文书功能；身份会话与案件归属用增量SQLite迁移，管理采集走管理员权限。每个后续子系统独立验证并记录真实状态。
**Tech Stack:** Python/FastAPI/Pydantic/SQLite、Vue TypeScript、原生微信、Capacitor、Electron。

用户已要求自主实施、不反复询问；方案沿用现有栈。会话采用随机Bearer令牌，数据库仅存SHA256；密码用PBKDF2-HMAC-SHA256，600000次迭代。网页会话仅保存当前标签页sessionStorage，不写localStorage；后台用户由本机CLI或管理员创建，无默认密码。旧案件owner为空并保留，由本机显式迁移认领，任何新用户都不能自动获得。

- [x] 写未登录401、A/B用户跨案件404、summary/deadline隔离、过期/撤销/禁用会话、登录限速与旧库原数据保持测试，先复现失败。
- [x] 实现auth_store/auth路由/CLI，增量owner_user_id索引，按用户限制所有案件查询和更新，管理采集POST要求admin；文书匿名生成不变。
- [x] 生成认证接口类型；实现登录、退出、管理员守卫与错误提示，旧浏览器workspace按用户隔离且旧键保留。
- [x] 持续按自身官方来源推进候选地区，保留未核验状态，不复用邻区来源；需要Word/真实网页QA后才允许发布。
- [x] 增加可配置部署入口，使手机可访问部署后端；只准备可验收部署包，不假称无公网地址/TLS时已公网运行。
- [x] OpenClaw真实接口探测；持久化公开问题及幂等重试；工作区导出、服务接收、AI复核分别记录，不能互相冒充。
- [x] CI运行只读类型漂移、严格编译、后端权限和客户端回归；实际运行结果与仅写workflow区别记录。
- [x] 真实浏览器登录/退出/匿名生成/来源绑定回归，合适的全量测试与安装包验收。通过后按子系统分批提交，更新Release与checkpoint，保留所有用户dirty文件。

**Review focus:** 不可把404变成越权存在性泄露；新账号不能接管旧案件；会话过期后UI清除私人状态；采集任务不能触发模型；生产备份、原件和用户资料不可进入GitHub制品。
