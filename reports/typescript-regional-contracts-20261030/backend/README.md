# Regional form contract backend

The backend field contract and source-bound HTTP path pass the focused tests. A temporary SQLite store containing the 185 currently generatable public localities produced all 364 document combinations through the real contract GET and contract-ID-bound generation POST. Every response was HTTP 200 with the expected source/version and validated form-contract headers, valid ZIP CRC and Word document/body XML. These are in-process ASGI checks, not browser downloads or new visual Word acceptance. Temporary store sequences are explicitly separate from live guide versions.

The selected implementation derives technical bounds from the existing request model and intersects them with an explicit adapter-specific list of actual slots. Exporting every field in the generic request model would advertise unsupported positions; separate hand-maintained model limits would drift. Existing model selection is extracted into `generation_request_model` and reused without changing the old request path. The current inventory has 13 adapters and 23 adapter/kind profiles. Exact EJS application/evidence/item shapes are 28/4/5, Zhejiang D/E worker shapes 23/5/4, Hunan has 27 application keys including embedded evidence, and Feidong uses its six line-oriented keys. Sichuan/reference exposes only fields consumed by its checked sample renderer. No province or neighboring-locality fallback grants a contract.

`build_form_contract(guide, template, kind, root=None)` returns schema v1 with a SHA256 contract ID over canonical context, fields, empty defaults and policy. Context includes the exact locality, source ID, version, template ID, kind, checked mode and adapter. Fields contain labels, the four agreed types, technical capacities and applicable copy/date/choice policies. Text is non-nullable; defaults are blank and lists start with one exact blank item. Hunan evidence remains part of the application. No signatures, dates, consent or official recipient are selected automatically.

An explicit root must contain the own original with matching SHA and path containment. Families with existing public proof contracts must also rebuild their proof from that root. These checks run before historical adapters that might otherwise read their default checkout. Empty or whitespace roots, missing originals, changed bytes and missing public evidence fail closed. The historical providers and sealed source bundles are unchanged.

`GET /api/regional-guides/form-contract` requires province, city, district, source_id, version, template_id and kind. It checks the current exact guide and then the own adapter. Mode comes from the checked server template. Generation may include `contract_id`; this new path rebuilds the current contract, rejects stale hashes with 409 and rejects unknown fields, invalid XML characters, capacity violations and invalid typed values with 422. The unbound older request path retains its existing model and normalization behavior. Generation adds `X-Guide-Version` alongside the existing source/origin headers. A request carrying `contract_id` also returns `X-Form-Contract-ID` from the successfully rebuilt and validated server contract. Error responses and older requests without a contract ID do not claim this header. A contract for another document kind is rejected even when source ID and version are identical.

The existing original-download route accepts optional source_id and version together. A partial binding or mismatch returns 409. Scope-only requests remain compatible. Successful originals carry `X-Guide-Source-ID`, `X-Guide-Version` and `X-Template-SHA256`, while retaining no-store caching.

Copy rules are technical slot policies. JS blank applications have nullable counts; blank strings become null. EJS counts are integers 1–30 without leading zeroes. Zhejiang D/E accepts existing leading-zero strings and preserves blank text. Hunan retains its free text or finite numeric copy slot with a 160-character capacity and no invented 1–30 rule. Reference and legacy independent evidence contracts do not advertise unbound copy keys. ISO calendar validation applies only to existing strict EJS date slots. Other date positions remain free text.

Feidong's policy carries the runtime Unicode version, compressed East Asian Width W/F ranges and field layout limits. It retains two party lines with display widths 40/50, nine wrapped request lines and ten fact lines. The table is generated once and cached, allowing another client runtime to use the same Unicode data. Feidong rejects control characters except LF. Runtime validation preserves raw text; `trim_text` declares the normalization already performed by older generation models or renderers. All capacities are explicitly marked as technical, not official filing requirements.

The final new suite passed 21 tests in 51.733 seconds, including real generation of all 364 combinations in 50.515 seconds. The older dispatch/model suite passed 19 tests in 16.920 seconds. Initial 14 missing-module RED tests, three hardening RED tests, root-evidence/root-order RED tests and a small-body huge-integer RED HTTP 500 were observed before their fixes; the huge integer now returns controlled 422. Two response-header RED tests were observed before the header fix. All 364 real ASGI records now assert and record the validated contract response ID; the wrong-kind negative case returns 409 without that header. Full diagnostic traces remain private. Shared-client parity passes across 23 profiles, 8,253 JSON vectors and 202 local JavaScript shape vectors; its separately pinned report is in the sibling shared-parity directory. Full-project tests, deployed API/browser acceptance and new visual rendering are separate integration gates managed outside this report. No live database was opened or changed, and no model, service or Git operation was performed by this work.
