# 接口契约、后端校验与构建验收

2026-10-30；版本 1.2.0-preview.2。只使用虚构表单和隔离测试数据，不提交仲裁申请，不调用模型推理，不启动 Windows Ollama。

## 实际改动

- 六个稳定路径从注册的 FastAPI 路由生成 OpenAPI、TypeScript 和 Pydantic 长度常量，离线导出禁止 DB/网络调用。当前不是全部 API 自动生成；区县表单仍使用自身模板的动态契约。
- 区县读表单与生成共享地区、来源版本、唯一模板和填写数据校验，保留当地适配器、合法旧请求及既有响应扩展字段。复现并修复邻区查询误命中、重复模板 ID 两个错误生成案例。
- 修复省级同步器不能读取 TS 导出、目录富化读取旧快照、声明生成忽略编译诊断、从不同目录运行生成器产物不同、桌面 `/` 同源 API 地址等问题。
- 版本统一到 config/client-release.json；check/build/plan/artifact 顺序执行并记录真实退出码、源码和制品 SHA。拒绝失败/空/旧/过期/漂移产物及路径越界。私有库、上传文件及 SQLite 不进回执或制品白名单；桌面源码图标仍进入指纹。
- Vite 静态文件保留旧 mtime 时，必须与指纹中同相对路径静态源码逐字节和 SHA 匹配，独立重验；没有改时间戳来伪造新构建。增量旧编译产物仍需经过验证的旧回执。

## 失败与重测

初次全量后端失败在已有旧JS测试加载器：它把所有require都替成同一文书对象，不能加载真实拆分模块。修复仅测试加载器后，5个相关测试和最终726项通过。保留早期失败日志，不把失败改称通过。

微信第一轮7页和富阳已通过，但下一次SDK响应超时；断开SDK后仅重试地区切换，富阳、建德、桐庐全部通过。没有改AppID、安全设置、真实账户或数据。桌面首次测试脚本误读不公开代理的/openapi.json，已修正测试为产品实际允许的health/catalog；未扩大代理路由。重叠的早期测试实例造成一次等待超时，串行重测通过。此前管线子任务报告记录17项和当时SHA；最终根集成增加图标案例为18项，以本文件和最终回执为准。
